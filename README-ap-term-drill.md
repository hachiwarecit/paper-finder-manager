# 応用情報 用語分類ドリル

IPA 応用情報技術者試験（レベル３）シラバス Ver.7.2 から用語を抽出し、
スマホで片手で解ける 4 択ドリルを単一 HTML として生成する。

オフラインで動く。外部通信・CDN・Web フォントは一切使わない。

- 用語 **5,158 語** ／ 中分類 **23** ／ 小分類 **96**
- 問題 **9,551 問**（仲間はずれ 5,158 ／ 分類当て 4,393）
- `dist/index.html` 単一ファイル・約 890 KB

---

## このドリルが問わないこと

**シラバスには用語ごとの説明文が存在しない。** シラバスが持っているのは
分類体系（大分類 → 中分類 → 小分類 → 項目）と、項目ごとの「用語例」という
用語名の羅列だけで、各用語に 200〜300 字の解説が付いた文書ではない。

したがってこのドリルは **分類の識別に限定** した出題をする。

| 種別 | 問い方 | 誤答の作り方 |
|---|---|---|
| 仲間はずれ | 「『システムの評価指標』に属さない用語はどれか」 | 誤答 3 語は指定した小分類の中から取る |
| 分類当て | 「『スループット』はどの分類の用語か」 | 誤答 3 つは同じ中分類の別の小分類から取る |

誤答は必ず「同じ箱」から取る。全体からランダムに選ぶと 1 つだけ明らかに
正解になってしまい、練習にならないため。箱は狭い順に
subtopic → topic → subcategory → category と緩める。

**解説文は一切生成していない。** 解答後に表示されるのは、用語の分類パスと、
IPA シラバスの「内容」原文（項目単位の説明であり、用語ごとの説明ではない）だけ。
規格番号・制定年・具体的数値を問う問題も作っていない。

同じ用語名が複数の小分類にまたがるもの（345 語）は、正解が一意に定まらないため
「分類当て」から除外している。「仲間はずれ」には使う。

## スマホに入れる

`dist/index.html` を 1 個持っていくだけでよい。データは HTML に埋め込み済みで、
オフラインで開ける。

### iCloud（iPhone）

1. `dist/index.html` を Mac の iCloud Drive に置く（またはブラウザの iCloud.com からアップロード）
2. iPhone の「ファイル」App → iCloud Drive → `index.html` をタップ
3. Safari で開く。共有 → 「ホーム画面に追加」でアプリのように起動できる

`file://` で開くため `localStorage` が使えないことがあるが、その場合は
メモリ内で動作し、エラーは出ない（セッションを閉じると進捗は消える）。
進捗を残したいなら GitHub Pages 経由が確実。

### Google ドライブ（Android）

1. `dist/index.html` を Google ドライブにアップロード
2. Android のドライブ App からダウンロード → Chrome で開く
3. Chrome のメニュー →「ホーム画面に追加」

ドライブのプレビューでは HTML が実行されない。**ダウンロードしてから開くこと。**

### GitHub Pages（進捗を確実に残すならこれ）

`https://` で配信されるので `localStorage` が確実に効き、復習キューが端末に残る。

1. GitHub でリポジトリの **Settings → Pages** を開く
2. Source を `Deploy from a branch`、Branch をこのブランチ、フォルダを `/dist` にする
3. 数分後 `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける
4. Safari / Chrome で「ホーム画面に追加」

> リポジトリが public なら、この URL は誰でも開ける。気になるなら
> リポジトリを private にする（Pages は有料プランが必要）か、iCloud / ドライブ経由にする。

## 元データを差し替えて再生成する

### 1. シラバスを用意する

IPA の配布ページから応用情報技術者試験のシラバス PDF を入手する。

```
https://www.ipa.go.jp/shiken/syllabus/
```

**PDF のまま食わせない。** この抽出器は `.docx` を入力に取る。PDF を直接読むと
段組みとテキストボックスの復元が不安定で、用語と説明文の対応が崩れる。
Word で PDF を開いて `.docx` として保存し直す（Word は PDF を編集可能な文書に変換できる）。

変換した `.docx` を次の場所に置く。

```
input/syllabus_ap_ver7_2.docx
```

`input/` は `.gitignore` に入れてある（再配布を避けるため）。

### 2. パイプラインを回す

```bash
python3 scripts/extract.py       # docx  -> data/terms.json, data/topics.json
python3 scripts/build_quiz.py    # terms -> data/quiz.json
python3 scripts/build_viewer.py  # quiz  -> dist/index.html
```

追加ライブラリは不要（標準ライブラリのみ）。

`extract.py` はカテゴリ別件数を出力する。**中分類が 23 個出ているかを必ず確認すること。**
ここが崩れると誤答選択肢が「同じ箱から取る」という前提を失い、ドリルとして機能しなくなる。

```
=== カテゴリ別件数 (中分類 23 個) ===
 1. 基礎理論              310
 2. アルゴリズムとプログラミング    176
 ...
```

### 3. シラバスのバージョンが変わったら

見出し構造が変わっている可能性がある。件数が大きくずれたら
`scripts/extract.py` の以下を確認する。

- `parse_toc()` — 目次から 大分類 / 中分類 / 小分類 を取る
- 本文走査の分岐 — `Heading1` = 小分類、`Heading2` = 項目
- `RE_CONTENT_END` — 「内容」文と「用語例」を分ける唯一の手掛かり（末尾が「。」か）

## PDF→Word 変換の癖と、その処理

元が PDF のため、素直に読むと壊れる。`extract.py` は次を個別に処理している。

| 現象 | 対処 |
|---|---|
| 本文がテキストボックスに 2〜3 重複製されている | 本文ストーリーのみ採用 |
| ルビが用語に混入（歪度・尖度 → 「わいせん」） | `w:rt` を除外 |
| 1 文が複数段落に折り返されている | 「。」まで連結してから内容/用語例を判定 |
| 項目見出し 28 件が `Heading2` でなく `ListParagraph` | 両方を項目見出しとして扱う |
| ①〜⑳ の枝マーカーが用語に接着 | マーカー行を用語例の切れ目として扱う |
| 括弧内の読点で誤分割 | 括弧の深さ 0 の読点だけで分割 |
| 語の途中に空白（`ベンチマーキン グ`） | 和文どうしに挟まれた空白のみ詰める |

`ベロシティ` は変換時に本文側で 1 文字欠落していたため、`extract.py` の
`CORRECTIONS` で個別に直している。同種の欠落を見つけたらここに足す。

## 操作

- 選択肢をタップした瞬間に正誤が出る。決定ボタンはない
- 間違えても正解は必ず緑で光る。探させない
- 解答後、正解と自分が選んだものの分類パスを並べて表示する
- 次へは**画面のどこをタップしても**進む
- キーボード: `1`〜`4` で選択、`Space` / `Enter` で次へ
- 1 セッション 10 問固定
- 間違えた問題は復習キューに入り、次のセッションで優先的に出る
- 終了画面は正答率を出さない。**間違えた用語の一覧**を出す
- 開始画面でカテゴリを複数選択できる（既定は全範囲）。「復習のみ」は 1 タップ
- ダークテーマ固定。アニメーションは正誤表示の一瞬だけで、`prefers-reduced-motion` を尊重する
